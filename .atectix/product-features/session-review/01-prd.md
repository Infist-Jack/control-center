# Paseo 会话复盘（session-review）

中控扩展说明（2026-10-02）：本文保留上游单节点设计。中控部署的节点范围、统一时区和失败行为以 [全节点扩展 PRD](../session-review-all-nodes/01-prd.md) 为准。

状态：2026-10-01 用户确认首版范围；2026-10-02 安装到本机 daemon 后按用户第一轮反馈收窄：范围只按项目、并行图作为唯一的会话列表、去掉「未纳管」标签、归纳层整体移出首版（见文末 TODO）。本文已按收窄后的范围改写。

## 用户需要与结果

用户在 Paseo 里选一个工作区和一个日期范围，看到这段时间这台机器上全部 agent 会话的时间线：每个会话做了什么、持续多久、哪些时刻 agent 停下来问他、他在哪里打断或纠正了 agent、agent 把什么写进了记忆，以及多个会话如何并行。可选地让一个 coding agent runtime 按用户自己写的提示词做归纳。目的只有一个：事后 review 和反思，不是工程监控。

## 已确认的基础

- Paseo 0.9.2 原生插件：工作区面板、侧栏页、插件 RPC（30 秒超时，长任务走启动与轮询）、服务端以 daemon 用户在节点本机运行。代码放在 control-center 的 `plugins/session-review/`，不改 Paseo 源码。
- 会话原始记录都在节点本机：Claude Code 为 `~/.claude/projects/<目录slug>/<session>.jsonl`，Codex 为 `~/.codex/sessions/<日期>/rollout-*.jsonl`。Paseo 的 `~/.paseo/agents/*.json` 记录每个 agent 对应的 provider 会话 id、工作区和目录。
- 两类记录都带时间戳，并以结构化方式记录：用户消息、助手文本、工具调用及参数、提问工具及其回答、用户打断、Codex 的 fork 与子线程关系、每轮 token 用量。Codex 的推理内容加密，不读。

## 首版范围

一个名为「复盘」的工作区面板，加一个同名侧栏页用于跨项目选范围。内容两层：以并行图为主体的会话时间线，和确定性的决策点列表。

首版不包含：任何 AI 归纳或分类、批注与复盘笔记、一键生成飞书文档、启发式决策点（问号结尾、否定词匹配等）、Codex 分叉树与 guardian 审查的展示、工具调用次数与 token 作为主视图内容、跨节点聚合、定时自动运行、对 agent 的任何干预。

## 聚合规则

- **单位是一个 provider 会话。** Codex 由 `forked_from_id` 产生的 fork 作为源会话下的分支展示；带 `parent_thread_id` 的子线程（guardian 审查等）和 Claude 子代理折叠进父会话，不单列。
- **归属按项目。** 由 Paseo 创建的 agent 用其记录归到项目；其余会话按 cwd 落在哪个项目根目录之下归属，worktree 自然归到主项目。终端里直接启动的会话同样纳入，不另加标记。
- **Claude 的续写副本折叠。** Paseo 恢复会话时 Claude 会另写一个以旧记录开头的新文件，只保留最长的一份，其余计入折叠数。
- **范围三个维度：** 项目，面板取所在工作区的项目，侧栏页可选任一项目或全部；日期范围，默认今天，按节点本地时区；分支，可选。
- **按活动归入，不按开始时间。** 会话只要在范围内有活动就显示，图上只画范围内的部分；开始早于范围的标「续」，展开里另给整个会话的起止。一个跨天会话会出现在它活跃的每一天。

## 页面与交互

### 范围选择

面板顶部：日期范围（今天、昨天、最近 7 天、自定义）、分支过滤。侧栏页多一个工作区选择器，其余相同。切换范围只读本地文件，不触发归纳。

### 概览

一行摘要：时间跨度、会话数、最大并行数、总活跃时长（重叠部分只算一次）、等待用户的总时长。

### 会话列表（即并行图）

没有单独的卡片列表。并行图的每一行就是一个会话，行首是开始时间和标题（最长 60 字，超出省略号），行内是该会话的运行段、等待段和决策点。点一行展开，展开里才有 provider、日期与起止、活跃时长、等待时长、用户发送的消息数、分叉与折叠说明、该会话的决策点，以及「查看消息」入口。

不展示最后一条消息、改动文件数、commit、工具与 token 统计、来源标记。

### 决策点

只取三类确定性事件，每条一行：时间、类型、原文摘录（不超过 100 字）、agent 随后做了什么（取其下一条文本的首句）。

| 类型 | Claude Code 的判定 | Codex 的判定 |
| --- | --- | --- |
| agent 提问 | `AskUserQuestion` 工具调用，答案取对应的工具结果 | `request_user_input_async` 调用及用户的回复记录 |
| 用户打断或拒绝 | 用户记录含 `[Request interrupted by user]`；工具结果含 CLI 固定的权限拒绝文案 | `turn_aborted` 且 `reason` 为 `interrupted` |
| 写入记忆 | `Write` / `Edit` 的目标路径位于 `.claude/projects/*/memory/` | 首版不判定（其工具为通用 exec，无确定性标记） |

不做任何基于文本模式的推测。判定规则集中在一处，每条规则附带记录样例作为测试。

### 并行图

横轴为时间，轴头标日期，跨天时每个零点再标一次日期并加深刻度线；刻度按宽度自动取 1、2、3、6 或 12 小时；轴的范围取范围内会话首尾向整点取整。三种段：agent 在运行（Codex 取 `task_started` 到 `task_complete`；Claude 取用户消息到该轮最后一条助手记录，轮内超过 15 分钟没有记录就切开）、等待用户（一轮结束到用户下一条消息，超过 90 分钟视为搁置而不是等待，不画）、空白为闲置或已结束。决策点以圆点标在对应位置，点击定位到决策点列表。

颜色只取 `theme.colors`：运行段用 `accent`，等待段用 `surface2` 或等效中性色，圆点用 `foreground`。深色与浅色主题下都要可辨，不使用固定色值。紧凑布局下退化为表格：每会话一行，列出起止、活跃、等待，点一行同样展开。

### 脱敏

抽取时统一打码：形如 API key 和 token 的字符串、`Bearer` 后的值、URL 路径中长度超过 20 的随机段、`.env` 类文件内容回显、带密码的 URL。打码后的抽取物才会落盘。

## 失败、重试与离开页面

- 某个会话文件无法解析时，其余会话照常展示，该会话标「无法解析」并给出文件路径。
- 抽取是后台任务：离开面板不取消，返回后可查看进度与结果；重复点击不会重复启动同一范围的任务。
- 插件重启后缓存仍在，未完成的任务不续跑，重新触发即可。
- 范围内会话数量超过上限（首版 200 个）时提示收窄范围，不静默截断。

## 验收标准

1. 在真实节点上选择一个项目和「昨天」，面板列出当日全部 Claude 与 Codex 会话，含终端直接启动的会话；Codex fork 挂在源会话下，guardian 子线程不出现；Claude 的续写副本只出现一次。
2. 并行图每行标题不超过 60 字；展开后只含 provider、日期起止、活跃、等待、消息数、分叉与折叠说明、决策点和「查看消息」。
3. 决策点列表中的每一条都能回溯到记录里的一个结构化事件；用 2026-09-30 的记录验证：至少能找出 AskUserQuestion 的 6 次提问、用户的 2 次打断、Claude 的 10 次记忆写入、Codex 的 3 次提问。
4. 并行图轴头有日期，跨天范围在零点再标日期；深色与浅色主题下均可辨认运行段、等待段和决策点；390px 宽度下退化为表格且无横向溢出。
5. 抽取物中不含记录里出现过的 token 与 key（用 2026-09-30 记录中已知的凭据样例做负向检查）。
6. 会话文件损坏、离开页面再返回两种情况下，面板行为符合「失败、重试与离开页面」一节。
