## 接入方式

- 引入 PR #1 的独立 `plugins/session-review/`，保留原时间线与确定性事件的产品行为；不修改现有公共 Skills 的工作区改动。
- 解析核心修复脱敏、异常结束、历史子会话、恢复扫描、活动日期、分支、递归 fork 和缓存并发问题，新增正确结果断言的回归测试，提升抽取缓存版本。
- 插件仅安装在中控。服务端通过既有 `paseo-nodes-use/scripts/node.sh` 与 `exec.sh` 发现节点、核验身份并执行采集。使用运维工作区；没有唯一匹配时让页面选择现有工作区，不创建新工作区。
- 将同一解析核心打包为无外部依赖的 Node 采集程序，按内容摘要缓存到节点的插件数据目录。使用已有 SDK 分段上传、校验后运行，原始会话不离开来源节点。输出经过脱敏、压缩和分块读取，避免终端滚动缓冲截断大结果。

## 服务与数据

- 日期范围统一解析为新加坡时区的绝对边界，再传给节点；客户端时间轴、日期与详情使用相同显示时区。
- 扫描以节点为独立任务单元，限制同时采集数量；失败与离线单独记录。中控汇总成功节点的卡片，标注结果完整性。
- 节点、provider 与本地会话 ID 共同确定全局 ID，项目同样带节点归属。详情通过节点路由按页读取，避免超长消息流超过 RPC/传输大小。
- 中控保留后台任务进度和结果，可恢复查看；任务失效时允许重试。页面默认全部节点，保留节点筛选和明确的节点状态；项目选项只显示名称，查询始终包含全部分支。

## 2026-10-03：定时快照实现

- 用 daemon 生命周期内的 `Snapshots` 替代按页面启动的 `Jobs`。启动先恢复快照，后台串行预热常用日期范围；每 300 秒启动一轮，同一时间最多一轮，每轮沿用 Fleet 的两个节点采集 worker。
- 快照以绝对起止日期作为键，共享给所有节点、项目筛选；后台汇总不受页面 200 会话限制，限制改为读取后按筛选结果检查。
- RPC 分为快速读取快照、手动触发后台更新和按需消息详情。目录也持久化，页面不再调用节点目录查询；前端轮询只访问中控内存。
- 每个范围完成后原子写入 `session-review/snapshots.json`，权限 0600，默认路径位于仓库外；保存最多 32 个范围和最近 8 个自定义范围、已选工作区。解析或格式版本变化会重建快照。
- 同范围采集失败时保留已有结果；部分节点离线时保留其旧数据并记录最后成功时间，成功且为空则清空旧数据。卸载清理 timer 并 abort，丢弃晚到的结果。
- 新增 6 项快照回归，涵盖 5 分钟计时、无网络读取、磁盘恢复、任务去重和取消、离线保留、自定义范围、跨天、损坏缓存、工作区恢复和先筛选后限量；共 22 项测试通过，类型检查和 collector 构建通过。

实际验证：已重载中控插件，状态 `running`；首轮三个常用范围均已保存，4 个登记节点全部成功，最近 7 天返回 69 个会话。快照约 128 KB，位于 `~/.paseo/session-review/snapshots.json`。复制真实快照进行只读基准：恢复约 20 ms，三个范围筛选分别约 0.56 / 0.23 / 1.18 ms，节点扫描调用数为 0；该数据不含客户端 RPC 和页面渲染耗时。
